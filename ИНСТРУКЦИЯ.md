# Что нажать, чтобы всё заработало

Инструкция рассчитана на работу **только через браузер** — терминал не нужен.
Делайте по порядку, каждый шаг занимает несколько минут.

---

## Шаг 1. Обновить базу данных

1. Откройте Supabase → ваш проект → слева **SQL Editor** → **New query**.
2. Откройте файл `supabase/migrations/001_marketplace.sql`, скопируйте **весь**
   текст и вставьте в окно запроса.
3. Нажмите **Run**.

Скрипт выполняется целиком или не выполняется совсем: если что-то пойдёт не так,
база останется в прежнем виде. Существующие товары, заказы и пользователи
сохраняются. Повторный запуск безопасен.

**Проверка.** Выполните в том же окне:

```sql
select slug, name, is_published from public.shops;
select id, commission_rate from public.app_settings;
```

Должны появиться строка с комиссией `0.1000` и мастерские для тех, у кого уже
были товары.

---

## Шаг 2. Сделать себя администратором

Замените почту на свою и выполните в SQL Editor:

```sql
update public.profiles
   set role = 'admin'
 where id = (select id from auth.users where email = 'ваша@почта.ru');
```

Если нужна ещё и своя мастерская (вы продаёте сами):

```sql
insert into public.shops (id, slug, name, is_published)
select id, 'lili', 'Лили Вяжет', true
  from auth.users where email = 'ваша@почта.ru'
on conflict (id) do nothing;
```

`slug` — это адрес страницы: латиница, цифры и дефис. Потом его можно поменять
в кабинете мастерицы.

---

## Шаг 3. Настроить адреса входа в Supabase

Supabase → **Authentication** → **URL Configuration**:

- **Site URL**: `https://ВАШ-ЛОГИН.github.io/lilivyazhet`
- **Redirect URLs**: добавьте две строки
  - `https://ВАШ-ЛОГИН.github.io/lilivyazhet/auth/callback/`
  - `https://ВАШ-ЛОГИН.github.io/lilivyazhet/**`

Без этого письма с подтверждением будут вести не туда.

---

## Шаг 4. Загрузить код на GitHub

1. Откройте свой репозиторий на GitHub.
2. **Add file** → **Upload files**, перетащите содержимое архива целиком
   (папки `pages`, `components`, `lib`, `styles`, `supabase`, `.github` и файлы
   в корне). Папки `node_modules`, `.next` и `out` загружать не нужно —
   их в архиве и нет.
3. Внизу нажмите **Commit changes**.

**Важно про имя репозитория.** В файле `next.config.js` строка
`const basePath = '/lilivyazhet';` должна совпадать с именем репозитория.
Если репозиторий называется иначе — исправьте её прямо на GitHub
(карандаш «Edit» у файла). Если подключите свой домен — поставьте `''`.

---

## Шаг 5. Прописать три секрета

GitHub → репозиторий → **Settings** → **Secrets and variables** → **Actions** →
**New repository secret**. Нужны три:

| Имя | Где взять |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | там же → Project API keys → `anon` `public` |
| `GH_PAT` | GitHub → Settings профиля → Developer settings → Personal access tokens → Tokens (classic) → Generate, право `repo` |

Ключ `anon` — публичный, он и должен попадать в браузер. Ключ
`service_role` в репозиторий **не кладут никогда**: он даёт полный доступ к базе.

После этого откройте вкладку **Actions** — сборка запустится сама. Через
пару минут сайт будет по адресу `https://ВАШ-ЛОГИН.github.io/lilivyazhet/`.

Если сборка не стартовала: **Actions** → выберите workflow слева →
**Run workflow**.

## Шаг 6. Подключить оплату (ЮKassa)

Пока этот шаг не сделан, сайт работает: заказы оформляются и сохраняются,
но покупатель видит сообщение, что оплата ещё не подключена.

### 6.1. Секреты для функций

Supabase → **Edge Functions** → **Secrets** (или Settings → Edge Functions):

| Имя | Значение |
| --- | --- |
| `YOOKASSA_SHOP_ID` | shopId магазина в личном кабинете ЮKassa |
| `YOOKASSA_SECRET_KEY` | секретный ключ (у тестового магазина начинается с `test_`) |
| `SITE_URL` | `https://ВАШ-ЛОГИН.github.io/lilivyazhet` (без «/» в конце) |

Необязательные, если в ЮKassa подключены «Чеки от ЮKassa»:
`YOOKASSA_SEND_RECEIPT` = `true`, `YOOKASSA_VAT_CODE` (по умолчанию 1 — без НДС),
`YOOKASSA_PAYMENT_MODE` (по умолчанию `full_prepayment`).

### 6.2. Две функции

Supabase → **Edge Functions** → **Deploy a new function** → редактор в браузере.

1. Имя `create-payment` — вставьте содержимое
   `supabase/functions/create-payment/index.ts`.
   Проверка токена (**Enforce JWT verification**) — **включена**.
2. Имя `yookassa-webhook` — вставьте содержимое
   `supabase/functions/yookassa-webhook/index.ts`.
   Проверку токена — **выключите**: ЮKassa не умеет передавать токен Supabase.

### 6.3. Уведомления в ЮKassa

Личный кабинет ЮKassa → **Интеграция** → **HTTP-уведомления**:

- адрес: `https://<ref-проекта>.supabase.co/functions/v1/yookassa-webhook`
  (`<ref-проекта>` — часть из Project URL);
- события: `payment.succeeded` и `payment.canceled`.

Функция не верит содержимому уведомления: из него берётся только номер платежа,
а сумма и статус перепроверяются напрямую у ЮKassa по секретному ключу. Если
суммы не совпали, заказ не станет оплаченным.

## Как всё работает дальше

**Мастерица**: подаёт заявку в своём кабинете → вы одобряете в админ‑панели →
у неё открывается кабинет мастерицы. Там она оформляет страницу, добавляет
работы с фото и видео, включает показ витрины и отправляет заказы.

**Покупатель**: складывает работы в корзину → на оформлении выбирает доставку
у каждой мастерицы → платит картой → видит статус и трек‑номер в кабинете.

**Вы**: в админ‑панели видите заявки, заказы, оборот, комиссию и список
«ждут выплаты». Выплаты сейчас делаются вручную (перевод мастерице), после
чего вы отмечаете заказ кнопкой «Выплачено».

## Частые вопросы

**Заказ появился, а денег нет.** Заказ создаётся до оплаты со статусом
«ждёт оплаты». Мастерица увидит его только после того, как деньги придут.

**Мастерица не видит своих работ на сайте.** Скорее всего, витрина не
опубликована: кабинет мастерицы → «Страница мастерской» → переключатель
«Мастерская видна покупателям».

**Видео не показывается.** Вставьте не адрес страницы, а «код для встраивания»
(iframe) со страницы видео. Поддерживаются VK Видео, Rutube, YouTube и
Одноклассники; файлы — до 50 МБ.

**Поменять комиссию.** Админ‑панель → «Настройки». Новая ставка применяется
к новым заказам, в старых остаётся та, что была на момент заказа.

## О чём стоит договориться отдельно

Это не программные задачи, но без них нельзя работать «по-белому»:

1. **Чеки.** Когда площадка принимает деньги за мастериц, налоговая ждёт
   определённой схемы фискализации. Уточните её в ЮKassa и у бухгалтера —
   от ответа зависит, включать ли `YOOKASSA_SEND_RECEIPT`.
2. **Персональные данные.** По закону 152-ФЗ данные россиян должны храниться
   в России, а Supabase размещён за рубежом. На старте с небольшим оборотом
   этим часто пренебрегают, но риск стоит обсудить с юристом; при росте
   базу переносят на российский хостинг.
3. **Выплаты мастерицам.** Сейчас переводы ручные. Автоматические возможны
   через «Безопасную сделку» ЮKassa — для неё нужен отдельный договор.
